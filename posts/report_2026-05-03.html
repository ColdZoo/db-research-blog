GPU加速方向

1. Tailwind: A Practical Framework for Query Accelerators

  • **arXiv ID**: [2604.28079](https://arxiv.org/abs/2604.28079)
  • **作者**: Geoffrey X. Yu, Ryan Marcus, Tim Kraska
  • **提交日期**: 2026年4月30日
  • **核心贡献**:

    • - 提出外部查询规划器框架，无需修改RDBMS内核即可集成查询加速器

    - 使用抽象逻辑计划(ALPs)和神经网络模型预测加速器收益

    - 在Redshift和DuckDB上实现透明查询重写

  • **性能提升**:

    • - TPC-H查询平均加速 1.38倍

    - 最大加速 29倍

  • **备注**: 软件级加速框架，非GPU专用，但架构可扩展

    • 2. Index-Assisted Stratified Sampling for Online Aggregation

  • **arXiv ID**: [2604.28141](https://arxiv.org/abs/2604.28141)
  • **作者**: Yunnan Yu, Zhuoyue Zhao
  • **提交日期**: 2026年5月1日
  • **核心贡献**:

    • - 针对实时数据分析的两阶段分层采样框架

    - 证明最优分层和样本分配策略

    - 设计贪婪和动态规划优化方法

  • **性能提升**:

    • - 相比索引辅助均匀采样最高 3倍加速

    - 相比经典扫描分层采样最高 98,708倍加速

  • **备注**: 专注于近似查询处理优化，不涉及GPU

    • 📚 持续关注的重点论文

    🔥 GPU加速 + 压缩 (交叉领域)

    3. GPU Acceleration of SQL Analytics on Compressed Data

  • **arXiv ID**: [2506.10092](https://arxiv.org/abs/2506.10092)
  • **作者**: Zezhou Huang, Krystian Sakowski, Hans Lehnert, Wei Cui, Carlo Curino, Matteo Interlandi, Marius Dumitru, Rathijit Sen
  • **提交日期**: 2025年6月 (v2: 2025年9月)
  • **核心贡献**:

    • - 直接在轻量级压缩数据上运行SQL查询的新方法

    - 支持RLE、索引编码、位宽缩减、字典编码等多种压缩方案

    - 支持多RLE列联合操作而无需解压

    - 利用PyTorch张量操作实现跨设备可移植性

  • **性能提升**:

    • - 相比商业CPU分析系统达到 一个数量级加速

    - 可处理无法放入GPU内存解压后的生产数据集

  • **意义**: 解决了GPU HBM容量限制问题，扩展GPU在大规模分析中的应用

    • 4. ZipFlow: a Compiler-based Framework to Unleash Compressed Data Movement for Modern GPUs

  • **arXiv ID**: [2602.08190](https://arxiv.org/abs/2602.08190)
  • **作者**: Gwangoo Yeo, Zhiyang Shen, Wei Cui, Matteo Interlandi, Rathijit Sen, Bailu Ding, Qi Chen, Minsoo Rhu
  • **提交日期**: 2026年2月9日
  • **核心贡献**:

    • - 基于编译器的GPU加速数据分析压缩数据传输优化框架

    - 将压缩算法按固有并行性分类为3种模式

    - 为每种模式设计通用调度策略

    - 端到端优化压缩→传输→解压工作流

  • **性能提升**:

    • - 相比nvCOMP平均提升 2.08倍

    - 相比CPU引擎(如DuckDB)加速 3.14倍

  • **测试基准**: TPC-H

    • 5. L3: A GPU-Native Co-Designed Data Format for Learned Lossless Lightweight Compression

  • **会议**: SIGMOD 2026 (班加罗尔)
  • **作者**: 夏有阳, 张峰(通讯), 潘俊达, 刘奕好, 官佳薇, 张焕晨, 杜小勇 (中国人民大学)
  • **核心贡献**:

    • - GPU原生学习型无损轻量级压缩格式

    - SLAP垂直存储布局：lane-major方式组织位打包残差流

    - Warp协作学习型解压：按分区映射线程块，按warp tile协作解码

    - GPU原生压缩流水线：完全在GPU上完成自适应分区、模型选择、元数据生成

  • **性能提升**:

    • - 编码速度比Tile和FastLanes-GPU快 3-6倍

    - 解压吞吐量 1.08-1.90 TB/s

    - 强相关数据压缩比高达 77倍

  • **意义**: 首个端到端GPU原生学习型压缩方案

    • 📦 编码/压缩方向

    6. Nacrith: Neural Lossless Compression via Ensemble Context Modeling and High-Precision CDF Coding

  • **arXiv ID**: [2602.19626](https://arxiv.org/abs/2602.19626)
  • **作者**: Roberto Tacconelli
  • **提交日期**: 2026年2月23日
  • **核心贡献**:

    • - 结合135M参数Transformer(SmolLM2-135M)与轻量级在线预测器集成

    - CDF精度从2^16升级到2^24，消除75%量化开销

    - Token级N-gram模型实现快速本地预测

    - 自适应log-space偏置头通过在线梯度下降纠正文档级误差

    - 基于置信度的LLM跳过加速高可预测token

    - 混合二进制格式(NC06)扩展到任意二进制文件

  • **性能提升**:

    • - enwik8: 0.9389 bpb (11.74%) - 超越FineZip 8%

    - alice29: 0.918 bpb - 超越CMIX v21 44%，ts_zip 20%

    - 使用比FineZip 小60倍的模型，无需微调

  • **资源需求**:

    • - 模型权重: ~500 MB GGUF

    - VRAM: ~1.2 GB/工作线程

    - 支持最多8个GPU并行

  • **意义**: 目前神经无损压缩的最先进成果

    • 🚀 GPU加速方向 (其他)

  • **arXiv ID**: [2409.17141](https://arxiv.org/abs/2409.17141)
