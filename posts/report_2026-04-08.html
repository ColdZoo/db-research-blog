一、GPU加速相关论文

1. GPU-RMQ: Accelerating Range Minimum Queries on Modern GPUs

  • **作者**: Lara Kreis, Justus Henneberg, Valentin Henkys, Felix Schuhknecht, Bertil Schmidt
  • **来源**: arXiv:2604.01811 [cs.DB]
  • **发表日期**: 2026年4月2日

    • 摘要: 范围最小值查询（RMQ）在字符串处理和数据库应用中频繁使用，包括生物序列分析、文档检索和网络搜索。本文提出了GPU-RMQ，一种基于分层方法的新方法，利用现代NVIDIA RTX显卡的光线追踪核心和CUDA核心来加速RMQ查询。

    关键贡献:

  • 采用分层方法构建范围最小值摘要层次结构，构建过程高度并行
  • 查询时仅处理层次结构中的相关部分，通过优化的大规模并行扫描操作进行
  • 混合架构设计，同时利用光线追踪核心和CUDA核心处理查询
  • 解决现有方法（LCA、RTXRMQ）内存开销大、索引构建时间长、查询吞吐量低的问题

    • 性能提升:

  • 相比LCA方法：**8倍**吞吐量提升
  • 相比RTXRMQ方法：**17倍**吞吐量提升
  • 相比优化的CPU方法：**4800倍**吞吐量提升
  • 索引构建时间提升高达**两个数量级**（约100倍）

    • 链接: https://arxiv.org/abs/2604.01811

    2. GPU Acceleration of SQL Analytics on Compressed Data

  • **作者**: Zezhou Huang, Krystian Sakowski, Hans Lehnert, Wei Cui, Carlo Curino, Matteo Interlandi, Marius Dumitru, Rathijit Sen
  • **来源**: arXiv:2506.10092 [cs.DB]
  • **发表日期**: 2025年6月11日

    • 摘要: GPUs凭借其大规模计算并行性和高带宽内存（HBM），非常适合加速SQL分析工作负载。然而，GPU HBM容量通常较小。本文提出了一套直接在轻量级压缩数据上运行查询的新方法，使用游程编码（RLE）、索引编码、位宽缩减和字典编码等方案。

    关键贡献:

  • 直接在压缩数据上执行查询的新方法
  • 处理多列RLE数据无需解压
  • 支持异构列编码（不同列采用不同编码方式）
  • 利用PyTorch张量操作实现跨设备可移植性

    • 性能提升:

  • 与最先进的商用纯CPU分析系统相比，实现了**数量级（10倍以上）**的加速
  • 在无法以未压缩形式放入GPU内存的生产数据集上验证

    • 链接: https://arxiv.org/abs/2506.10092

    3. ZipFlow: a Compiler-based Framework to Unleash Compressed Data Movement for Modern GPUs

  • **作者**: Gwangoo Yeo, Zhiyang Shen, Wei Cui, Matteo Interlandi, Rathijit Sen, Bailu Ding, Qi Chen, Minsoo Rhu
  • **来源**: arXiv:2602.08190 [cs.DB]
  • **发表日期**: 2026年2月9日

    • 摘要: 在GPU加速的数据分析中，当数据规模超过GPU内存容量时，由于有限的PCIe带宽，从CPU到GPU的数据传输开销成为性能瓶颈。本文提出了ZipFlow，一个基于编译器的框架，用于优化GPU加速数据分析中的压缩数据传输。

    关键贡献:

  • 基于编译器的框架，优化GPU数据分析中的压缩数据传输
  • 根据压缩算法固有的并行性将其分为三种不同的模式
  • 为每种模式采用通用的调度策略，有效利用不同架构下GPU的计算能力
  • 提供灵活、高性能和整体化的优化

    • 性能提升:

  • 在TPC-H基准测试上评估
  • 相比最先进的GPU压缩库（nvCOMP）：**2.08倍**性能提升
  • 相比基于CPU的查询处理引擎（DuckDB）：**3.14倍**加速

    • 链接: https://arxiv.org/abs/2602.08190

    4. GPU-Accelerated Algorithms for Graph Vector Search: Taxonomy, Empirical Study, and Research Directions

  • **作者**: Yaowen Liu, Xuejia Chen, Anxin Tian, Haoyang Li, Qinbin Li, Xin Zhang, Alexander Zhou, Chen Jason Zhang, Qing Li, Lei Chen
  • **来源**: arXiv:2602.16719 [cs.DB, cs.AI]
  • **发表日期**: 2026年2月10日

    • 摘要: 近似最近邻搜索（ANNS）支撑许多大规模数据挖掘和机器学习应用，随着数据集规模增长，高效检索越来越依赖GPU加速。本文对基于GPU加速的图向量搜索算法进行全面综述和实验研究。

    关键贡献:

  • 建立GPU优化策略的详细分类体系
  • 阐明算法任务与GPU硬件执行单元之间的映射关系
  • 在8个大规模基准数据集上对6种领先算法进行全面评估
  • 揭示不同系统设计在可扩展性和内存使用方面的关键权衡

    • 主要发现:

  • 距离计算是主要计算瓶颈
  • CPU-GPU之间的数据传输是实际大规模延迟的主要影响因素
  • 为设计可扩展、鲁棒的GPU加速ANNS系统提供明确指南

    • 链接: https://arxiv.org/abs/2602.16719

    二、数据编码/压缩相关论文

    5. Zero-Cost NDV Estimation from Columnar File Metadata

  • **作者**: Claude Brisson
  • **来源**: arXiv:2603.24606 [cs.DB]
  • **发表日期**: 2026年3月16日

    • 摘要: 本文提出一种方法，用于估计列式文件格式中某列的唯一值数目（NDV），仅利用现有文件元数据——无需额外存储或数据访问。利用两种互补信号：（1）对字典编码存储大小方程进行反推；（2）跨行组统计唯一的最小/最大值，并结合"优惠券收集模型"反推。

    关键贡献:

  • 零成本NDV估计方法，仅利用列式文件已有元数据
  • 双信号互补估计器：基于字典编码存储大小反推 + 基于行组min/max统计
  • 轻量级分布检测器动态选择适合的估计器
  • 可推广至ORC、F3等具有字典编码和分区统计的列式格式

    • 应用场景:

  • 基于成本的查询优化
  • GPU内存分配
  • 数据剖析

    • 链接: https://arxiv.org/abs/2603.24606

    6. Huff-LLM: End-to-End Lossless Compression for Efficient LLM Inference

  • **作者**: Patrick Yubeaton, Tareq Mahmoud, Shehab Naga, Pooria Taheri, Tianhua Xia, Arun George, Yasmein Khalil, Sai Qian Zhang, Siddharth Joshi, Chinmay Hegde, Siddharth Garg
  • **来源**: arXiv:2502.00922 [cs.LG, cs.AR]
  • **发表日期**: 2025年2月2日

    • 摘要: 随着大语言模型（LLM）规模不断增长，在小型边缘设备上运行最先进的LLM变得越来越困难。标准技术主张通过量化或剪枝等有损压缩技术来解决这个问题。然而，这些有损技术已被证明会以不可预测的方式改变模型行为。本文提出Huff-LLM，一种端到端的无损模型压缩方法。

    关键贡献:

  • 端到端无损模型压缩方法
  • 支持在云、磁盘、主存、片上存储器等各处存储压缩后的权重
  • 不仅减少主存占用，还降低片上权重加载的带宽需求
  • 在压缩模型上进行推理时实现延迟降低和能效提升

    • 优势:

  • 与量化、剪枝等有损方法不同，保持模型行为不变
  • 全场景压缩支持

    • 链接: https://arxiv.org/abs/2502.00922

    三、研究趋势分析

    当前热点趋势

    1. 直接在压缩数据上执行查询

    - 越来越多的研究关注避免解压开销，直接在压缩数据上进行计算

    - GPU加速的压缩数据查询成为重要方向

    2. 混合CPU-GPU架构

    - 针对大规模数据集的向量搜索，混合架构成为主流

    - 如何优化CPU-GPU数据传输成为关键挑战

    3. 光线追踪核心用于数据库操作

    - 利用GPU RT核心加速范围查询等数据库操作

    - GPU-RMQ展示了RT核心在数据库领域的潜力

    4. LLM与数据压缩结合

    - 使用LLM进行无损文本压缩（FineZip、Huff-LLM）

    - 但LLM-based压缩尚未准备好替代轻量级CPU压缩算法
