1. FineZip: Pushing the Limits of Large Language Models for Practical Lossless Text Compression

  • **Authors:** Fazal Mittu, Yihuan Bu, Akshat Gupta, et al. (UC Berkeley)
  • **Venue:** arXiv 2024
  • **Link:** https://arxiv.org/abs/2409.17141

    • Abstract:

    FineZip presents a novel LLM-based text compression system that combines online memorization and dynamic context to reduce compression time. It achieves a 54x speedup over prior LLMZip system (from 9.5 days to 4 hours for 10MB text) while maintaining ~50% better compression ratios than traditional algorithms like gzip and zstd.

    Key Contributions:

  • Online memorization mechanism leveraging LLM's contextual learning
  • Dynamic context management for improved efficiency
  • Uses Llama3-8B as the base model
  • **Compression improvement:** ~50% over traditional algorithms
  • **Speed improvement:** 54x over LLMZip

    • 2. GPU Acceleration of SQL Analytics on Compressed Data

  • **Authors:** Zezhou Huang, Krystian Sakowski, Hans Lehnert, et al.
  • **Venue:** arXiv 2025 (PVLDB submission)
  • **Link:** https://arxiv.org/abs/2506.10092

    • Abstract:

    This work proposes methods for running SQL queries directly on compressed GPU data using lightweight encoding schemes (RLE, index encoding, dictionary encoding, bit-width reduction). The approach enables processing datasets larger than GPU memory without full decompression overhead.

    Key Contributions:

  • Direct query processing on compressed data without decompression
  • Support for heterogeneous column encodings
  • PyTorch tensor operations for cross-device portability
  • **Performance:** Order-of-magnitude speedup over CPU commercial systems
  • **Compression schemes:** RLE, index encoding, dictionary encoding, bit-width reduction

    • 3. The FastLanes File Format (VLDB 2025)

  • **Authors:** Azim Afroozeh, Peter Boncz (CWI)
  • **Venue:** VLDB 2025 / PVLDB Vol 18
  • **Link:** https://www.vldb.org/pvldb/vol18/p4629-afroozeh.pdf

    • Abstract:

    FastLanes is a new open-source big data file format designed for modern data-parallel execution (SIMD or GPU). It improves compression ratio over Parquet while strongly accelerating decompression, providing a win-win over state-of-the-art formats.

    Key Contributions:

  • Designed for SIMD/GPU data-parallel execution
  • Better compression ratio than Parquet
  • Faster decompression speed
  • Open-source format for big data

    1. Theseus: A Distributed and Scalable GPU-Accelerated Query Processing Platform

  • **Authors:** Felipe Aramburú, William Malpica, et al. (21 authors)
  • **Venue:** arXiv 2025
  • **Link:** https://arxiv.org/abs/2508.05029

    • Abstract:

    Theseus is a production-ready enterprise distributed accelerator-native query engine that balances data movement, memory utilization, and compute tasks. It uses specialized asynchronous control mechanisms coupled with hardware resources for network communication, data preloading, and GPU compute.

    Key Contributions:

  • Accelerator-native distributed query engine
  • Asynchronous control for data movement and GPU compute
  • Page-locked host memory allocation to reduce fragmentation
  • **Performance:** 4x faster than Databricks Photon at same cost
  • **Scale:** Handles 100TB (TPC-H/TPC-DS SF100k) with just 2 DGX A100 nodes

    • 2. Vortex: Overcoming Memory Capacity Limitations in GPU-Accelerated Analytics

  • **Authors:** Yichao Yuan, Advait Iyer, Lin Ma, Nishil Talati
  • **Venue:** VLDB 2025
  • **Link:** https://arxiv.org/abs/2502.09541

    • Abstract:

    Vortex addresses GPU memory limitations for large-scale analytics by optimizing IO primitives to leverage all available PCIe links in multi-GPU systems. It routes data through other GPUs to target GPUs for IO-intensive tasks, especially beneficial when other GPUs run compute-intensive AI workloads.

    Key Contributions:

  • Optimized IO primitives utilizing all PCIe links
  • Novel programming model separating GPU kernel dev from IO scheduling
  • GPU zero-copy memory access for lazy materialization
  • **Performance:** 5.7x faster than Proteus baseline, 2.5x better price-performance than DuckDB

    • 3. Rethinking Analytical Processing in the GPU Era (Sirius)

  • **Authors:** Bobbi Yogatama, Yifei Yang, et al. (12 authors)
  • **Venue:** arXiv 2025
  • **Link:** https://arxiv.org/abs/2508.04701

    • Abstract:

    Sirius is an open-source GPU-native SQL engine prototype providing plug-and-play acceleration for data systems. It treats GPU as the primary engine using libcudf for high-performance relational operators, integrating via standard Substrait query representation.

    Key Contributions:

  • GPU-native SQL engine with Substrait integration
  • Plug-and-play acceleration for existing databases
  • Uses libcudf for relational operators
  • **Performance:** 8.3x cost efficiency vs DuckDB on TPC-H
  • **Performance:** 7.4x on ClickBench, 12.5x with Apache Doris

    • 4. CIDER: Boosting Memory-Disaggregated Key-Value Stores

  • **Authors:** Yuxuan Du, Xuchuan Luo, Xin Wang, et al.
  • **Venue:** VLDB 2026 (Accepted)
  • **Link:** https://arxiv.org/abs/2604.03007

    • Abstract:

    CIDER addresses I/O redundancy in memory-disaggregated KV stores caused by optimistic synchronization. It proposes pessimistic synchronization with global write-combining and contention-aware schemes to reduce cross-node redundant I/O.

    Key Contributions:

  • Pessimistic synchronization for memory-disaggregated architectures
  • Global write-combining to reduce cross-node I/O
  • Contention-aware synchronization for low-contention scenarios
  • **Performance:** Up to 6.6x throughput improvement on YCSB
